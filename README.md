# 一隅记账 · Yiyu Ledger

一个无需服务器和账号的 Android 本地记账应用。手动记账、预算、日历和统计都在手机上完成；主动授权后，也可尝试从付款通知或可访问的付款页面生成账目候选。

项目仓库：[krst4l/yiyu-ledger](https://github.com/krst4l/yiyu-ledger)。

**当前 v0.3.0 为实验版本，自动识别仍在适配中。** 微信付款页面识别尚未解决，通知路径尚未经过真实付款通知验证。应用可能漏记、误记或重复，请以支付平台和银行正式记录核账。

## 功能

- 手动记录支出、收入、退款和转账，编辑商户、分类、日期及备注。
- 按月浏览和搜索流水，设置月预算，添加自定义分类。
- 用日历查看每日收支，用统计页查看已确认账目的走势和分类分布。
- 可选通知识别与付款页面识别，按来源应用分别授权。
- 在“待核对”检查候选；日期不明的记录不计入汇总，页面、微信通知、银行和电商候选均需核对。
- 本地 SQLite 保存账目，支持 CSV 导出和不含账单原文的采集诊断。

## 安装与使用

可自行构建调试 APK，公开安装包以仓库的 [Releases](https://github.com/krst4l/yiyu-ledger/releases) 为准。Android 8.0（API 26）或更新系统可安装，实际兼容性仍需分别验证。

1. 安装 APK，打开一隅记账，即可手动记账。
2. 如需自动识别，进入“我的 → 自动记账”，阅读说明并开启总开关，仅选择需要的来源。
3. 通知识别需要系统“通知使用权”；页面识别需单独开启选项并授予无障碍服务权限。侧载应用可能需要先在应用详情中允许受限制的设置，入口随系统变化。
4. 从右上角进入“待核对”，检查金额、商户、日期和重复记录后再确认。识别不到时可手动补记，无需重新付款。

自动识别及页面识别默认关闭，预选微信和支付宝不代表已经开始采集。后台清理可能中断服务；可按设备设置允许后台运行、锁定最近任务，但这些设置不保证常驻。系统授权关闭后须手动重新开启。

## 识别支持状态

下面区分已有规则和实际验证结果，**不代表已支持各平台全部场景**。

| 来源或方式 | 当前状态 |
| --- | --- |
| 手动记账、账本、日历、统计 | 已在一加 13 查看竖屏界面；横屏、配置变化及异常路径尚未完成实机验收 |
| 支付宝付款页面 | 一笔“交易成功”的外卖账单已核对商户与金额正确，保存为待核对；日期未确认，未提取到明确交易号，其他模板未验证 |
| 支付宝内淘宝“等待确认收货”账单 | 当前未适配；等待收货不能等同于未付款 |
| 微信付款页面 | 主空间实机仍仅返回空根节点，暂不能识别；具体限制来源未确定 |
| 微信付款通知 | 已有受支持标题与无会话结构的保守规则，全部待核对；尚无真实付款通知验证 |
| 支付宝、云闪付通知 | 有规则入口，真实新付款通知未验证 |
| 淘宝、拼多多、京东、抖音 | 有候选规则入口，尚无适配成功证据，需核对 |
| 银行通知 | 仅处理已选银行来源的通知，候选需核对；不读取银行页面，尚无实机适配成功证据 |
| 新增或其他来源 | 选中应用不代表已有适配规则，不读取未知应用页面 |

详细样本、节点诊断和证据边界见 [设备验证记录](docs/device-validation.md)。通知标题和规则分数不能认证交易真实性；应用不能访问微信、支付宝或银行的完整交易数据库，也不会绕过受保护页面。

## 数据与隐私

应用未声明网络权限，没有在线 AI、遥测、广告 SDK 或云端账本。通知与页面原文只在内存中短暂解析，不保存完整原文、不截图、不自动点击或输入。页面读取先做有界的来源和安全检查，发现输入、密码、聊天或敏感语义等情况会整页放弃；第三方页面提供的语义并不完整，不能保证识别所有私人内容。

结构化账目保存在应用私有目录，**数据库没有额外加密**。CSV 导出未加密，当前不支持回导，不能作为完整恢复备份；系统文件提供方可能把导出同步到自己的云服务。卸载、清除应用数据或设备损坏可能导致账本丢失。完整说明见 [PRIVACY.md](PRIVACY.md)。

同一采集事件和明确交易标识用于去重，不会仅因金额相同合并消费。没有明确交易号的不同页面会话仍可能生成重复候选；钱包付款和银行卡扣款也可能对应同一笔消费。未知日期的记录留在待核对，不计入汇总。

识别异常时，先在“我的 → 自动记账”核对应用开关、系统实际授权和最新诊断时间。“收到事件”“规则处理完成”或旧诊断都不代表新增账目；“最近账目处理”可能早于最后事件，请同时检查待核对列表。

## 构建

需要 JDK 17 或 21、Android SDK Platform 35 和 Build-tools 35.0.0，并接受相关工具许可。设置 `JAVA_HOME`、`ANDROID_HOME`（或 `ANDROID_SDK_ROOT`）；也可在未提交的 `local.properties` 配置 `sdk.dir`。

项目使用 Gradle Wrapper 8.9、Android Gradle Plugin 8.7.3，最低 API 26，编译与目标 SDK 为 35。

Windows：

```powershell
.\gradlew.bat assembleDebug
```

macOS / Linux：

```sh
sh ./gradlew assembleDebug
```

产物为 `app/build/outputs/apk/debug/app-debug.apk`。PowerShell 也可执行 `./build-apk.ps1`，生成项目根目录的 `YiyuLedger.apk`。首次构建需联网下载工具及依赖，手机应用运行不需要服务器。

调试 APK 使用构建环境的调试签名；保留同一应用 ID 和签名才能覆盖更新。请勿为解决签名冲突直接卸载已有账本，卸载会丢失应用私有数据。正式发布需另行管理签名，密钥与密码不要提交到仓库。
