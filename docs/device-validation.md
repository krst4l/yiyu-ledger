# 设备验证记录

项目：[一隅记账 · Yiyu Ledger](https://github.com/krst4l/yiyu-ledger)。版本：v0.3.0。记录日期：2026-10-28。

本记录区分设备观察、规则行为和人工核对结果。只有一台设备及少量样本，不构成准确率统计或平台兼容性承诺。APK 构建成功、服务连接和规则匹配分别说明不同环节，均不能单独证明账目正确。

## 环境与范围

- 设备：一加 13（PJZ110），系统报告 Android 17 / API 37。
- 通过 ADB 检查系统授权、服务状态及应用的固定诊断元数据，使用相同应用 ID 和签名覆盖安装，保留既有数据。
- 检查了应用竖屏下的账本、日历、统计、记账和诊断页面；横屏、分屏、配置变化及故障路径尚未完成实机验收。
- 记录对应更名前的 v0.3.0 调试构建；品牌更名后的源码尚未重新构建。此前仅执行 APK 调试构建，未运行测试、lint、类型检查或开发服务器。
- 未抓取完整第三方账单、通知正文、截图或界面树，未读取账本数据库明细，未新增虚构交易，也未自动确认候选。应用自身的私有截图不随源码分发。

## 实际结果

| 对照对象 | 观察 | 可以得出的结论 |
| --- | --- | --- |
| 应用自身窗口 | 根可见，根子节点 9；完整检查 46 个节点，其中 30 个可见 | 服务可取得本应用的结构。该检查不读取文字，不能验证第三方内容或付款规则 |
| 微信分身历史账单 | 仅一个不可见根，无可读文字 | 该样本无法进入交易识别；分身具有独立空间边界 |
| 主空间微信账单、支付凭证及普通设置页 | 既有读取模式下，修正不可见容器遍历后仍仅一个不可见根，可见和文字节点均为 0 | 空树现象并非仅出现在分身或付款网页；具体原因未确定 |
| 新版主空间微信历史付款详情 | `include_containers_requested=true`、`include_containers_active=true`、`event_window_matches_root=true`；节点 1，可见与文字节点 0，根子节点 0，根可见性及重要性均为 false | 普通不重要节点选项在本次读取中生效，仍未取得内容，微信页面识别尚未解决。不能据此认定由微信保护或特定 Android 版本导致 |
| 微信付款通知 | 没有可用的真实付款通知样本 | 通知路径尚未实机验证；历史付款页面不能代替通知验证 |
| 支付宝“交易成功”的外卖账单 | 68 个节点，均可见，37 个提供文字，2 个 WebView 样式节点；根可见，敏感节点计数 0。顶部排序商户规则报告 `header_found`，支出候选保存为 `pending / saved_pending`；人工核对商户、金额正确 | 仅这一笔商户、金额经核对，候选未自动确认入账；日期未核对，未提取明确交易号，不能推广到其他模板 |
| 支付宝内淘宝“等待确认收货”账单 | 状态不同于“交易成功” | 当前未适配，未将此状态加入成功判定；等待收货不能等同于未付款 |
| 其他付款来源及真实新付款通知 | 没有适配成功样本 | 代码存在规则入口不代表实机适配完成 |

节点计数只反映特定时刻系统提供的元数据。敏感节点计数为 0 不证明没有敏感内容；应用自身结构检查成功也不保证第三方页面可访问。

## 读取方式与边界

页面采集最多访问 200 个节点、8192 字符。不可见容器不读取自身文字或内容描述，但可继续检查同包子节点的元数据；完整有界树通过安全检查后，才读取系统明确标记可见的节点。发现输入、密码、聊天、敏感标记、来源不明、跨应用、缺失子节点或超限等情况，整页放弃。

微信非聊天页面的单次采集中临时请求公开的 `FLAG_INCLUDE_NOT_IMPORTANT_VIEWS`，只尝试取得系统可提供的普通不重要节点；结束后恢复原标志，恢复失败停止后续页面读取，等待重新连接或成功刷新配置。此选项不提升服务身份或绕过系统保护，不扩大来源白名单、安全检查及数量边界。

对应诊断只保留请求与生效布尔值、根子节点数（最多 200，未知为 -1）、根重要性、事件窗口是否匹配根的布尔值及时间，不保存窗口或节点标识。`root_not_visible` 表示该次采集根不可见且子树也未提供可见节点；`tree_no_visible_text` 表示现有检查后没有取得可用于识别的文字。提前拒绝也可能使文字节点计数为零，不能据此断言屏幕没有文字。

通知先进行有界支付标题筛选，再检查会话结构；有 `MessagingStyle`、消息数组、历史消息数组或可回复输入时，不读正文，也不读取这些数组。仅受支持微信标题且无这些结构时，允许尝试标准字段的消息类别通知；其他来源的消息类别仍拒绝。微信通知最高分为 80，一律进入待核对。标题只是模板提示，不能认证官方身份或排除昵称仿冒。

## 支付宝商户与去重

无标签商户回退仅用于支付宝页面的支出候选。完整安全检查后，可将同一批已读可见节点的顶部文字按屏幕位置排序；节点须完整位于根窗口上半部，高度不超过窗口四分之一。辅助文字最多 24 行、4096 字符；坐标和原文只在内存使用，不改变全文及金额解析。无有效辅助信息时，使用原文本前 24 个非空行。

规则检查名称、金额与“交易成功”的相邻关系，或详情标题、名称样式行与成功状态的相邻关系。独立、摘要或可安全拆分的合并金额须与已解析金额精确一致；剩余名称带金额、字段标签、金额不匹配或名称冲突时放弃。带标签商户字段兼容同一行及换行形式。`header_found` 只说明分支匹配，正确性仍依靠实际核对。

仅同一事件或明确交易号对应、金额与方向一致、原记录仍待核对且缺商户时，才补充商户及原为“其他”的分类；保留金额、日期、状态和备注，不按同额合并。当前支付宝样本没有明确交易号，不同页面会话可能产生重复候选。

## 后台与诊断解读

在该设备上观察到清理后台后无障碍授权关闭，系统记录过 `o-stop` 停止。具体触发组件或规则未确定，不能归因于覆盖安装。最近任务锁定及允许后台运行可作为排查方法，但不保证常驻；授权关闭后需在系统设置手动开启，应用不会自动恢复授权。

诊断分别保留最后事件、结构采样、规则样本及最近账目处理的时间，它们可能不是同一次事件，也不是实时连接证明。“收到事件”不代表识别成功；“重复”及 `merchant_supplemented` 不代表新增候选。“规则未匹配”的实际原因以固定拒绝分支为准，不能一概归因为缺少成功状态。

支付宝规则诊断只保存最多 48 个固定字段或分支代码、最多 24 组连续字符类型、方向及提取状态；排序顶部类型带有 `spatial_header` 标记。微信通知诊断只保存固定模板种类、标题支持与会话结构布尔值。所有诊断均不保存真实字符、组内字符数量、财务字段值或完整原文，且可在应用中清除。详见 [隐私说明](../PRIVACY.md)。
