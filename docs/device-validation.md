# 自动记账设备记录

目前只有下述一台设备的部分记录，其他品牌和版本待验证。设置方法与反馈入口见 [安卓机型适配指南](android-compatibility.md)。

记录日期：2026-10-28。设备：一加 13（PJZ110），当时系统报告 Android 17 / API 37；微信版本未记录。识别观察来自 v0.3.0，相关采集代码已包含在公开 v0.4.0 中。

## 已有结果

| 场景 | 结果 |
| --- | --- |
| 应用自身页面 | 可取得可见结构；只检查节点元数据，未读取文字 |
| 主微信历史付款详情、付款凭证及普通设置页 | 仅返回一个不可见空根，没有可见文字，无法生成候选 |
| 微信分身历史账单 | 同样未取得可见文字 |
| 微信付款通知 | 暂无真实通知样本，未验证 |
| 支付宝“交易成功”的一笔外卖账单 | 用户核对商户、金额正确；日期未核对，保存为待核对候选 |
| 支付宝内淘宝“等待确认收货” | 尚未适配 |
| 其他银行、电商及付款通知 | 暂无适配成功样本 |

## 微信页面诊断

问题跟踪：[微信历史付款详情无法生成候选 #1](https://github.com/krst4l/yiyu-ledger/issues/1)。

```text
include_containers_requested=true
include_containers_active=true
event_window_matches_root=true
nodes=1
visible_nodes=0
text_nodes=0
root_children=0
root_visible=false
root_important=false
```

读取普通容器的标志已生效，仍未取得内容。问题发生在页面采集阶段，具体原因未确定；不能据此认定由微信保护或某个 Android 版本导致。历史页面的结果也不能代替真实付款通知验证。

## 排查说明

- 保持无障碍服务开启，使用已有历史账单即可，无需新付款。
- 设备曾在清后台后关闭无障碍授权；具体触发原因未确定，权限关闭后需手动开启。
- 诊断的事件、结构、规则和账目处理时间可能不同；收到事件或匹配规则不等于新增账目。
- 公开反馈只需设备与应用版本、服务状态、固定原因及上述计数，不上传账单正文、完整节点树或数据库。

新增设备记录请使用 [机型兼容性反馈表](https://github.com/krst4l/yiyu-ledger/issues/new?template=device-compatibility.yml)，注明验证的是手动记账、通知候选还是付款页面候选，以及实际核对过的字段。

当前记录不代表所有设备或模板的识别结果。数据处理范围见 [隐私说明](../PRIVACY.md)。
